# דירוגי הקהל — מפרט עיצוב

תאריך: 2026-09-14

## למה

הדירוג הוא עמוד השדרה של כל המשחק. הוא קובע את הדראפט, את הסימולציה, את
הלוחות ואת כל מוד במשחק — והיום הוא הערכה של אדם אחד.

במקביל, כל התגיות הקיימות (`js/tags.js:32-59`) הן **עובדות שהדאטה מוכיחה**:
מלך שערים, מבקיע דו-ספרתי, זוכה אליפויות, נאמן למועדון. אף אחת מהן איננה
דעה. וזה בדיוק הפער: **הדאטה לא יכולה לדעת** מי היה מלך הדרבי, מי בעט
עונשין, מי היה מנהיג, ומי לא מומש. אין לזה מקור ולעולם לא יהיה — חוץ
מהאנשים שראו אותו משחק.

הפיצ'ר הזה פותח את הדלת הזאת: הקהל מדרג, מתייג וכותב; הבעלים מאשר; הדאטה
משתפרת באמת.

`js/mg-versus.js` כבר רושם כל חוסר-הסכמה עם הדאטה — מקומית בלבד, עם הערה
בקוד שזה "החומר הגולמי לדירוגי קהל בהמשך". זה ההמשך.

## החלטות שהתקבלו

| נושא | ההחלטה |
|---|---|
| מה מדרגים | מספר + תגית + שורת טקסט קצרה |
| מה מדרגים עליו | **שחקן-בעונה** (הכרטיס ממילא פתוח על אחד). השיא נגזר |
| השפעה על המשחק | **רק אחרי אישור ידני בדשבורד** |
| איך דירוג מאושר מגיע למשחק | **סקריפט שכותב ל-`js/data.js`** — לא אוברריד חי |
| משטחים | כרטיס השחקן בדראפט + עמודי `/player/` הציבוריים |
| מוד "דירוגי הקהל" | **לא עכשיו.** נבנה כשיש נפח |
| מדד ציבורי | **ממוצע גזום** (10% מלמעלה, 10% מלמטה) — תווית "דירוג קהל ממוצע" |
| הרשאה | מספר ותגית: גם אנונימי (`client_id`). טקסט: **חובה מחובר** |

## 1 · החוויה

### מצב סרק — שורה אחת

בכרטיס השחקן (`js/player-card.js`), שורה אחת מתחת לדירוג הרשמי:

```
דירוג 84   ·   דירוג קהל ממוצע 82 ⟨37⟩   ·   ⭐
```

זה כל מה שהפיצ'ר תופס כשלא נוגעים בו. **לא מודאל, לא מסך, לא כפתור בולט.**

### נגיעה — הכרטיס נפתח למטה

1. **חוגה** מעוגנת על הדירוג הרשמי. גוררים; שחרור = נשלח. סימון-רפאים מראה
   איפה הקהל יושב היום. תנועה אחת, אפס הקלדה. טווח חופשי 40–99.
2. **מדף תגיות** — עשרה צ'יפים, נגיעה אחת בוחרת אחת (נגיעה שנייה מבטלת).
3. **שורה אחת** — 80 תווים, מוצגת רק למשתמש מחובר. שאר המשתמשים רואים
   "התחבר כדי לכתוב" ולא תיבה מושבתת.

### אחרי ההצבעה

השורה מתכווצת חזרה ומראה גם את מה שאתה אמרת:

```
אתה 86  ·  דירוג קהל ממוצע 82 ⟨38⟩  ·  🎯 בעיטות נייחות
```

הצבעה חוזרת **מעדכנת** — מותר לשנות דעה, ולא נוצרת כפילות.

### מצב ריק — התכנון החשוב ביותר

ביום הראשון אין לאף שחקן הצבעות, וזה יימשך שבועות. המצב הריק הוא המצב
הרגיל של הפיצ'ר בתחילת חייו, ולכן הוא מעוצב ראשון ולא אחרון:

```
עוד אין דעות על שלומי ארבייטמן — תהיה הראשון
```

עם החוגה כבר פתוחה ומוכנה. **הזמנה, לא באג.**

מתחת ל-5 הצבעות לא מוצג מספר קהל כלל — רק מונה ("3 הצבעות עד שהדירוג
ייחשף"), שגם משמש כתמריץ.

### מדף התגיות

עשר תגיות, כולן **ניטרליות** (בלי העמסה עדתית/מועדונית) וכולן דברים
שהדאטה לא יכולה להוכיח:

| | |
|---|---|
| 🎯 בעיטות נייחות | 👑 מלך הדרבי |
| 🧠 מנהיג | ⚡ מהירות יוצאת דופן |
| 🪄 קסם ברגליים | 🧱 קשוח |
| 🔥 שחקן של משחקים גדולים | 💔 לא מומש |
| 🩹 פציעות רדפו אותו | ❤️ אגדת קהל |

לשוערים מוחלפות שלוש: 🎯 בעיטות נייחות ← 🧤 רפלקסים,
🪄 קסם ברגליים ← 🙌 יציאות, ⚡ מהירות ← 🦶 משחק ברגליים.

התגיות האלה **תיאוריות בלבד** בשלב הזה. הן לא נושאות אפקט במשחק. הבעלים
יכול, בנפרד ובהחלטה מפורשת, לקדם תגית שהתייצבה לתוך `star_tags.csv` עם
אפקט באחוזים — אבל זה לא קורה אוטומטית ואף פעם לא כתוצאה מהצבעות בלבד.

## 2 · הנתונים

### `player_votes`

| עמודה | טיפוס | הערה |
|---|---|---|
| `player_key` | text | שם מנורמל (אותו נרמול כמו `pcNorm`) |
| `season` | text | `"2001/02"` |
| `voter` | text | `user_id` אם מחובר, אחרת `client_id` |
| `is_user` | boolean | האם ההצבעה מחשבון מזוהה |
| `ovr` | smallint | 40–99, נאכף ב-CHECK |
| `tag` | text | מתוך רשימה סגורה, nullable |
| `updated_at` | timestamptz | |

מפתח ייחודי: `(player_key, season, voter)` → `upsert`, כך שהצבעה חוזרת
מעדכנת ולא מוסיפה.

RLS: הכנסה/עדכון מותרים דרך RPC בלבד. **קריאה ישירה חסומה לחלוטין** —
הצבעות גולמיות אף פעם לא נחשפות.

### `player_notes`

| עמודה | טיפוס | הערה |
|---|---|---|
| `player_key`, `season` | text | |
| `user_id` | uuid | **חובה** — טקסט על אדם אמיתי צריך שם מאחוריו |
| `body` | text | ≤ 80 תווים |
| `status` | text | `pending` \| `approved` \| `rejected` |
| `created_at` | timestamptz | |

קריאה ציבורית **רק** ל-`status = 'approved'`.

### `player_ratings` — הצבר ציבורי

`VIEW` (או טבלה מרוענת, לפי הביצועים) שהיא הדבר היחיד שהעולם קורא:

```
player_key · season · n · avg_trimmed · tag_top · tag_top_n · tag_2nd
```

`avg_trimmed` = ממוצע לאחר השמטת 10% העליונים ו-10% התחתונים (במינימום
הצבעה אחת מכל קצה כש-`n ≥ 5`). זה ממוצע אמיתי — כך שהתווית "דירוג קהל
ממוצע" מדויקת — והוא חסין להצבעות קיצון בדיוק כמו חציון.

**המונה יוצא תמיד; הדירוג לא.** שורה עם פחות מחמש הצבעות מוחזרת עם `n`
ועם `avg_trimmed = NULL`. זה מה שמאפשר את המצב "עוד 2 הצבעות והדירוג
ייחשף" — סינון השורה כולה היה הורג את המונה שאמור לשמש תמריץ, והכרטיס היה
נופל למצב הריק בדיוק כשמישהו כבר הצביע.

### RPCs

- `vote_player(player_key, season, ovr, tag)` — upsert, מגביל קצב
  (≤ 40 הצבעות לשעה לכל `voter`), מאמת שהתגית ברשימה הסגורה ושהשחקן-עונה
  קיים בדאטה.
- `submit_player_note(player_key, season, body)` — מחובר בלבד, הערה אחת
  לשחקן ליום, נכנסת כ-`pending`.
- `report_note(note_id)` — כל אחד, מסמן לבדיקה.

**כל פונקציה plpgsql שמוסיפה למערך חייבת `array_append`, לעולם לא
`|| 'key'`.** זה הבאג שהרג את לוח הגאונטלט ואת כל ההישגים ב-2026-08-23.

### `profiles` הוא `username`, לא `display_name`

מיגרציה שמתייחסת ל-`display_name` נכשלת ב-push.

## 3 · הדשבורד

סקשן חדש ב-`admin.html`: **⭐ דירוגי הקהל**.

### טבלת המחלוקות

כל מי שהקהל חולק עליו — `|avg_trimmed − official| ≥ 2` וגם `n ≥ 5` —
ממוין לפי `|הפרש| × log(n)`, כך שמחלוקת חזקה עם הרבה מצביעים עולה למעלה
ולא מחלוקת אקראית של חמישה אנשים.

לכל שורה: שם · עונה · מועדון · רשמי · קהל · `n` · פער · פיזור ההצבעות
(היסטוגרמה זעירה) · התגית המובילה · **✅ קבל** · **🗑️ בטל**.

"קבל" כותב ל-`rating_approvals` — **ולא נוגע במשחק.** "בטל" מסתיר את השורה
ומוריד אותה מהתור עד שיצטברו עוד הצבעות.

### תור ההערות

בדיוק כמו תור הפוסטים שכבר עובד: טקסט · שם המשתמש · השחקן · ✅ / 🗑️.
**שום שורה לא מוצגת בפומבי לפני אישור.**

## 4 · איך דירוג מאושר מגיע למשחק

סקריפט `scripts/apply_crowd_ratings.js`:

1. מושך את `rating_approvals` שטרם הוחלו.
2. משנה את ה-`ovr` של אותו שחקן-עונה ב-`js/data.js`.
3. מחשב מחדש `peak_ovr` לשחקן אם העונה שהשתנתה היא השיא שלו.
4. מסמן את השורות כמוחלות, וכותב `crowd_ratings_log.csv` עם לפני/אחרי.

בדיוק אותו דפוס שבו כימיה, תגיות ותכונות כבר נשלחות: דאטה נוצרת מחוץ
לזמן ריצה. **הסימולציה נשארת דטרמיניסטית ועובדת אופליין**, ואין שום מצב
שכשל רשת משנה בשקט את האיזון או את הלוחות.

מריצים כשרוצים, לא בכל אישור.

## 5 · הדרך לעמודים

היום מגיעים ל-1,570 עמודי `/player/` **רק מגוגל**, וכל עמוד הוא מבוי סתום.
שלוש נגיעות:

1. **כרטיס השחקן** מקבל בתחתית `העמוד המלא של X ↗` → `/player/<slug>/`.
2. **עמוד השחקן** (`scripts/player_pages.js` — מחויב לריפו, בניגוד ל-
   `build_seo_pages.js` שהוא gitignored) מקבל את אותו ווידג'ט דירוג, ובתחתית
   חיפוש שחקנים, כדי שמבקר מגוגל לא ייתקע. זה דורש להזריק את `supabase-js`
   ואת הווידג'ט לתבנית — היום העמודים סטטיים לגמרי חוץ מ-AdSense.
3. **כניסה אחת בתפריט** — `👥 שחקנים`, מדריך עם חיפוש. הערה: מצוקת מקום
   בסרגל הנייד מתועדת ב-`js/nav-drawer.js`, אבל המגירה פותרת אותה — כפתור
   שישי בתוכה תקין.

## 6 · מה לא נבנה עכשיו

- **מוד "דירוגי הקהל"** — דראפט שמשתמש בדירוגי הקהל במקום ברשמיים. דורש
  מאות שחקנים עם `n ≥ 5` כדי להיות בר-משחק בכלל. נבנה כשהצינור מלא.
- **תגיות קהל עם אפקט** — נשקל בנפרד, לשחקנים עם הסכמה מובהקת.
- **Story mode** — שיחת תכנון נפרדת.

## 7 · סיכונים

**בני אדם אמיתיים.** טקסט חופשי על כדורגלן ישראלי חי הוא חשיפה משפטית
ומוסרית, והבעלים הוא בעל התוכן. ההגנות: חובה מחובר, מודרציה לפני פרסום,
קישור דיווח על כל הערה מאושרת, ומשפט תנאים קצר בנקודת השליחה. גם כך זו
ההחלטה הכי כבדה במפרט — היא מתועדת כאן במפורש כדי שתהיה החלטה ולא תקלה.

**בריגייד.** ממוצע גזום + הצבעה אחת לזהות + הגבלת קצב. אנונימי מגדיל נפח
ומגדיל חשיפה; `is_user` נשמר כדי שאפשר יהיה להפריד בדשבורד אם יידרש.

**התחלה קרה.** מתוכנן כחלק מהעיצוב (סף 5, מונה כתמריץ, מצב ריק שהוא
הזמנה), לא כתיקון בדיעבד.

**אזהרת פרויקט — "שדה שאף אחד לא מציב הוא שדה שנגרר".** הבאג החוזר ביותר
בפרויקט הזה. ווידג'ט הדירוג נפתח מתוך כרטיס שחי בכל המודים; מצב הצבעה
שנשמר מכרטיס אחד ולא נוקה ייראה על הכרטיס הבא. **המצב נקרא לפי
`player_key + season` בכל פתיחה, ואף פעם לא נשמר בין פתיחות.**

**בדיקה ויזואלית.** `js/player-card.js` מעצב חלקים מהכרטיס inline. לפני
עיצוב מ-CSS יש לבדוק אם המאפיין כבר מוצב inline, ולבדוק מול מועדון בהיר
ולא רק כהה (`docs` ו-`css/club.css` מתעדים את הכלל). הרמוניה עם
`--era-club` / `--era-ink` נשמרת.

## 8 · סדר בנייה

1. מיגרציה: `player_votes`, `player_notes`, `player_ratings`, שלושת ה-RPCs.
2. ווידג'ט הדירוג בכרטיס השחקן (כולל המצב הריק), מחובר ל-RPCs.
3. סקשן הדשבורד — טבלת המחלוקות + תור ההערות.
4. `scripts/apply_crowd_ratings.js`.
5. הווידג'ט + החיפוש בעמודי `/player/`, ורגנרציה.
6. כניסת `👥 שחקנים` בתפריט.
